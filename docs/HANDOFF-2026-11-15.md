## 1. Tujuan proyek

Lost & Found UNKLAB adalah portal untuk mahasiswa melaporkan, mencari, dan mengembalikan barang di lingkungan kampus.

Fase yang telah disetujui pengguna memprioritaskan:

1. UI baru bergaya editorial SaaS, diinspirasi oleh referensi Talentflow Webflow.
2. Landing page publik.
3. Login **satu peran saja: mahasiswa**.
4. Main menu/dashboard mahasiswa setelah login.
5. Backend lokal dan database sebagai pondasi pengembangan fitur berikutnya.

Pengguna meminta UI menjadi prioritas utama. Jangan menganggap proyek ini siap produksi hanya karena login lokal sudah berfungsi.

## 3. Fitur yang telah selesai

### Frontend

| Rute | Status | Implementasi |
| --- | --- | --- |
| `/` | Selesai | Landing page publik: hero, statistik komunitas, proses 3 langkah, preview laporan, closing CTA, footer. |
| `/login` | Selesai | Login mahasiswa dua kolom pada desktop, form responsif, validasi dasar, server error, loading submit, show/hide password, kredensial demo. |
| `/app` | Selesai | Halaman yang dilindungi auth: header akun, welcome panel, statistik laporan, search/filter tipe, kartu laporan, loading/error/no-results state. |

Router sengaja dibuat kecil di `src/router.jsx` memakai History API (`pushState`/`popstate`), bukan React Router. Jangan menambahkan React Router di tengah perubahan kecil; gunakan itu hanya jika navigasi bertambah kompleks dan migrasikan semua rute dengan sengaja.

### Backend

| Endpoint | Status | Perilaku |
| --- | --- | --- |
| `POST /api/auth/login` | Selesai | Menerima `email` dan `password`; mengembalikan user dan menulis cookie session. |
| `POST /api/auth/logout` | Selesai | Menghapus session map dan cookie. |
| `GET /api/auth/me` | Selesai | Mengembalikan profil mahasiswa sesi aktif; `401` bila tidak login. |
| `GET /api/reports` | Selesai | Mengembalikan laporan seed; memerlukan session. |

Backend berjalan di port `3001`; Vite melakukan proxy `/api` ke sana melalui `vite.config.js`.

### Database

`server/db.js` membuat SQLite otomatis di:

```text
server/data/lost-and-found.db
```

File database diabaikan oleh Git. Inisialisasi idempotent membuat tabel berikut:

| Tabel | Tujuan |
| --- | --- |
| `users` | Pengguna mahasiswa dengan email unik dan `password_hash`. |
| `reports` | Barang hilang/ditemukan; relasi ke pemilik laporan. |
| `claims` | Pondasi klaim laporan found; belum memiliki UI atau endpoint kerja. |

Seed membuat satu mahasiswa serta empat contoh laporan.

### Autentikasi

- Password di-hash dengan `bcryptjs` (bukan disimpan teks biasa di SQLite).
- Cookie `lf_session` memakai `httpOnly` dan `sameSite: 'lax'`.
- Session disimpan pada `Map` di memori proses Node dengan masa 8 jam.
- Frontend memakai `credentials: 'include'` melalui `src/lib/api.js`.
- Kunjungan `/app` tanpa user diarahkan ke `/login`; user yang sudah login mengunjungi `/login` diarahkan ke `/app`.

**Batasan penting:** session **hilang setelah server restart** karena masih berada di memori. Ini cukup untuk demonstrasi lokal, bukan produksi.

## 5. Cara menjalankan dan memverifikasi

### Prasyarat lokal

- Node.js modern dengan dukungan ES modules (proyek diuji dengan Node `v24.19.0`).
- npm.
- Tidak memerlukan server database eksternal untuk fase saat ini.

### Perintah

```bash
npm install
npm run dev
```

`npm run dev` menjalankan Vite dan Express bersamaan dengan `concurrently`. Buka URL yang dicetak Vite (biasanya `http://localhost:5173`).

Untuk production build frontend:

```bash
npm run build
```

### Kredensial demo

| Email | Password |
| --- | --- |
| `student@unklab.ac.id` | `unklab123` |

Kredensial di atas memang ditampilkan sebagai bantuan **khusus lingkungan lokal/demo**. Jangan gunakan akun ini atau `secure: false` pada cookie untuk deployment produksi.

### Pemeriksaan yang telah dilakukan

- `npm run build` berhasil setelah implementasi.
- Inisialisasi SQLite berhasil: user seed dan empat laporan ada.
- Password seed diverifikasi tidak muncul sebagai teks biasa di database.
- Server Express berhasil startup pada `http://localhost:3001`.

### Pemeriksaan yang belum dapat dilakukan oleh agent sebelumnya

- Tes HTTP end-to-end dari sandbox gagal karena socket localhost diblokir oleh lingkungan agent, bukan karena response aplikasi yang terbukti gagal.
- Preview visual melalui browser in-app timeout ketika mengakses localhost.

**Tugas pertama agent berikutnya:** jalankan `npm run dev` di lingkungan lokal normal dan secara manual uji login valid, login salah, refresh `/app`, logout, search, dan filter. Catat/atasi error nyata jika ada.

## 7. Persyaratan dan batasan proyek

### Wajib dipertahankan

1. **Hanya ada role mahasiswa** pada fase ini; jangan menambahkan dashboard/admin flow tanpa arahan pengguna.
2. UI baru harus tetap satu bahasa visual dengan landing/login/dashboard yang sudah dibuat.
3. Frontend hanya boleh berkomunikasi ke API melalui `src/lib/api.js`; komponen presentasi tidak boleh memanggil `fetch` langsung.
4. Password tidak boleh disimpan atau dikirim kembali dalam bentuk plain text.
5. Endpoint yang menampilkan data mahasiswa harus tetap membutuhkan auth.
6. Status report tidak boleh bergantung pada warna tanpa label teks.
7. Database lokal, `node_modules`, file `.env`, dan build output tidak boleh dicommit.
8. Jaga versi perubahan tetap kecil dan lakukan build sebelum commit.

### Batas fase sekarang

- Tidak ada registrasi mahasiswa mandiri.
- Tidak ada reset password atau integrasi SSO/Google.
- Tidak ada upload foto nyata.
- Tidak ada kemampuan membuat, mengubah, menghapus, atau melihat detail laporan.
- Tidak ada claim workflow, chat, notifikasi, atau admin.
- Tidak ada deployment, SMTP, service database hosted, rate limiting, CSRF strategy formal, atau persistensi session setelah restart.

## 8. Ketidaksesuaian/utang teknis yang perlu diketahui

1. **CTA “Buat laporan” tidak melakukan pembuatan laporan.** Ini sengaja placeholder visual sesuai scope awal, tetapi perlu dibuat menjadi feature berikutnya.
2. **Preview laporan landing bersifat statis.** Landing belum mengonsumsi SQLite/API karena endpoint report saat ini sengaja terlindungi session.
3. **“Recent activity” dashboard masih copy statis.** Belum ada model atau endpoint `activity`.
4. **Session in-memory.** Semua user logout saat Express restart; gunakan penyimpanan session yang persisten sebelum production.
5. **Cookie lokal:** `secure: false` hanya benar untuk HTTP localhost. Production harus memakai HTTPS, cookie `secure: true`, secret/config environment, dan hardening session.
6. **Tidak ada automated tests.** Endpoint dan routing belum punya test suite.
7. **Tidak ada validasi skema formal.** Validasi login masih manual; input report belum ada.
8. **Tidak ada pagination/filter server-side.** Dashboard memfilter laporan yang sudah dimuat di browser, layak untuk seed kecil saja.
9. **Komponen dashboard lama masih tersisa tetapi tak dipakai.** Bersihkan hanya pada commit terpisah setelah audit import.
10. **Global CSS padat.** Format/refactor tanpa mengubah UI untuk meningkatkan maintainability sebelum fitur UI besar.
11. **Routing fallback deployment belum ditangani.** Hosting SPA harus mengarahkan deep links (`/login`, `/app`) ke `index.html`.

## 9. Rekomendasi pekerjaan lanjutan

Urutan ini menjaga prioritas pengguna: pengalaman Lost & Found lengkap sebelum perluasan peran atau infrastruktur besar.

### Prioritas 1 — laporan barang yang benar-benar bisa dibuat

1. Buat route dan halaman protected, misalnya `/app/reports/new`.
2. Tambah endpoint `POST /api/reports` dengan auth dan validasi ketat.
3. Buat form type Lost/Found, title, category, location, description, tanggal, dan status awal.
4. Tambah `GET /api/reports/:id` serta halaman detail report.
5. Setelah create, kembali ke dashboard dan tampilkan laporan baru dari SQLite.
6. Tambah test API untuk validasi input, auth, dan ownership.

**Keputusan yang perlu dikonfirmasi sebelum mulai:** strategi upload foto (lokal untuk demo, object storage, ukuran/format yang diizinkan) dan daftar kategori lokasi kampus.

### Prioritas 2 — claim dan proses pengembalian

1. Buat endpoint/halaman klaim untuk report `Found`.
2. Tambah bukti kepemilikan dengan perlindungan privasi.
3. Buat state klaim dan langkah verifikasi.
4. Tampilkan timeline aktivitas dari event nyata, bukan copy statis.

### Prioritas 3 — kualitas dan keamanan sebelum deployment

1. Tambah test runner (misalnya Vitest + Supertest) untuk auth, route guard, dan report API.
2. Tambah linting/formatting dan format `global.css`.
3. Pisahkan schema, seed, database access, auth middleware, dan HTTP route ke modul kecil.
4. Pindahkan session dari `Map` ke persistent store atau signed session solution.
5. Konfigurasikan environment (`PORT`, cookie settings, origin, session secret) dengan `.env.example` tanpa secret nyata.
6. Tambah CSRF/origin policy, rate limiting login, logging aman, dan error handling yang sesuai deployment.
7. Ganti SQLite dengan PostgreSQL hanya ketika target deployment/multi-user concurrency memerlukannya; jangan lakukan migrasi prematur.
